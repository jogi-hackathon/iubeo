# 3 人で 1 戦を通しで遊ぶ手順

issue #84「ゲームフローを通しで遊べるようにする」の通し確認(人手)の手順書。
対象は、デプロイ環境と、手元(`devenv`)のどちらでもよい。

## 0. 完了条件(#84 より)

- 別々のブラウザ 3 つ(3 人分)から 1 戦を最後まで遊べる
- `victory` と `defeat` の両方で終わることを確認する(**console のログでよい**)

`victory` と `defeat` は、それぞれ別の 1 戦で確認する。
1 戦の所要は、既定の設定(3 フェーズ × 30 秒 + intermission 10 秒 × 2 + 決着まで最大 40 秒)で**約 2 分半**。

## 1. 準備

### 1.1 人数分の「別のプレイヤー」を用意する(最初の落とし穴)

プレイヤーの識別は HttpOnly Cookie(`iubeo_player`)なので、**同じブラウザの別タブ・別ウィンドウでは同じ人**になり、3 人にならない。
次のどれかで Cookie を分ける。

- **同じブラウザのユーザープロファイルを 3 つ**作る(Chrome: `chrome://settings/manageProfile` → 追加。ウィンドウ右上のアイコンで切り替える)
- **別のブラウザ**を使う(Chrome / Firefox / Safari)
- **端末を 3 台**(一番確実)
- macOS の Chrome を `user-data-dir` を分けて 3 つ起動する(付録 A)

確認: 各ブラウザの開発者ツール → Application → Cookies に `iubeo_player` があり、**3 つで値が違う**こと。

### 1.2 環境

**(A) デプロイ環境** — 3 人が同じ URL を開くだけ。設定は既定(3 人・3 フェーズ × 30 秒)。
**(B) 手元** — 付録 A のとおり `devenv up` で起動する。開く URL は **`http://localhost:5173`**(`127.0.0.1` は不可。理由は §6)。

### 1.3 全員で共有しておくこと

- 3 人とも、最初から最後までブラウザを閉じない(閉じると再接続になるが、その間もゲームは進む)
- 詰まったら console(開発者ツール)を開く。決着・切断の理由は `[game]` / `[gameFlow]` でログに出る
- 1 人が記録係を兼ね、各フェーズの HUD と最後の console を控える(スクリーンショット/コピー)

## 2. 通しの手順

### 手順 1: room でマッチングを始める(3 人)

1. 3 人がそれぞれ URL を開き、起動が終わって room(机のある部屋)に入る。
1. 机の天板の**右手前にある緑のボタン**(マッチングを始める仮のボタン)を、画面中央の照準で狙って**左クリック**する。

確認すること:

- HUD(画面上中央)に「マッチング中… N秒」が出る。ボタンはオレンジに変わる。
- もう一度クリックすると取り消せる(「マッチング中…」が消える)。
- 3 人とも押すと、白い覆いのあと **sandbox** に切り替わる。

> マッチングの待機列は、最後に確認されてから 10 秒で外れる。ボタンを押したまま放置せず、すぐ 3 人がそろうようにする。
> ボタンは狙いが少しでも外れると机(ワークスペース)を触ってしまい、ファイルを作る操作になる。照準をよく見て押す。

### 手順 2: 開始を待つ

全員が sandbox につながるまで HUD に「他のプレイヤーを待っています…」が出る。
人間全員がつながると自動で始まり、HUD が次の表示になる。

```
フェーズ 1　残り 30秒
自分のタスク:
☐ 書き込み
```

確認すること:

- **フェーズ番号**と**残り秒数**が出て、秒数が減っていく
- **自分のタスク**が一覧で出る(`read_edit` には、対象ファイルの色の四角が付く。誰かが持っている間は出ない)

### 手順 3: フェーズを進める(各自が自分のタスクを全部こなす)

タスクは 3 種類。**自分のタスクを全部終えないと、締切で脱落する。**

- **書き込み(write)**
  1. 手ぶらで、自分の机(ワークスペース)を狙って左クリック → 2 秒後に新しいファイルを手に持つ
  1. 中央の山(ディレクトリ)を狙って左クリック → 山に入り、タスク達成
- **画像生成(image_generation)**
  1. 手ぶらで、自分の区画のイーゼル(キャンバス)を狙って左クリック → 2 秒後に画像のファイルを手に持つ
  1. 山を狙って左クリック → 山に入り、タスク達成
- **読み込みと編集(read_edit)**
  1. 手ぶらで山を狙って左クリック → **俯瞰ビュー**が開く。HUD に出ている**色の四角**と同じ色の紙を、マウスで狙って左クリック → 手に取る(取ると俯瞰が閉じる)。俯瞰から出るには**右クリック**か Esc
  1. 自分の机を狙って左クリック → 2 秒後に編集済みになる
  1. 山を狙って左クリック → 山に入り、タスク達成

コツと注意:

- **手ぶらで山**を触ると俯瞰ビュー(取り出す選択)、**ファイルを持って山**を触ると「入れる」。間違えない
- 作業中(2 秒)は移動と視点がロックされる。終わるまで待つ
- 自分のタスクは HUD に ☑ が付く。全員が終えると、締切前でも intermission に入る

### 手順 4: 脱落と観戦(全員が終えられなかったとき)

締切までに未達だった人は脱落する。

- 画面が赤くなって「脱落」が出たあと、**FlyCamera の観戦**に切り替わる(WASD で移動、マウスで視点)
- HUD に「観戦中(物には触れられません)」が出る。**物には触れられない**
- 観戦している間も、残った人のゲームは続く

### 手順 5: フェーズ 2・3(intermission をはさむ)

- intermission(10 秒)の間は HUD が「インターミッション」になる
- 次のフェーズが始まると、タスクは増える(全体 = フェーズ番号 × 開始人数。3 人なら 3 → 6 → 9 件を、生存者で分ける)
- 脱落者が出ると、その分が生存者に再分配される

### 手順 6: 決着(最後のフェーズを終える)

最後のフェーズを生存者 1 人以上で終えると、生き残った人はライターを使える。

1. 自分の机の天板の右手前の**ライター置き場**が使えるようになる
1. 手ぶらでライター置き場を狙って左クリック → ライターを持つ
1. 山を狙って左クリック → 火がつく。10 秒後に `victory`
   - 誰も火をつけなくても、30 秒たつと `victory`

### 手順 7: 決着の確認(3 人)

決着すると、3 人の console に次のどちらかが出る。

```
[game] 決着: victory {decidedAt: "…", outcome: "victory"}
[game] 決着: defeat  {decidedAt: "…", outcome: "defeat"}
```

HUD には数秒だけ「結果: 勝利 (victory)」/「結果: 敗北 (defeat)」が出て、**3 人とも room へ戻る**。

## 3. victory で終わらせる

- **最後のフェーズを 1 人以上生き残る**のが条件。生存者全員が、各フェーズで自分のタスクを締切までに全部終える
- 生き残ったあとは、ライターで火をつける(手順 6)。火をつけなくても 30 秒で `victory`
- 3 人で 3 フェーズは忙しい。**手元で確かめるときは付録 B で 1 フェーズに短縮する**と確実

## 4. defeat で終わらせる

- **生存者が 0 人(全員脱落)になった時点**で `defeat`
- 一番簡単なのは、**フェーズ 1 で 3 人とも何もしない**。30 秒後に全員が脱落して `defeat`(このとき、脱落の演出のあとすぐ結果になるので、観戦にはほとんど移らない)
- 1 人でも生き残るとゲームは続く。そのときは、脱落した人が観戦になることを確認できる

## 6. うまくいかないとき

- **3 人そろわない**: 全員が同じプレイヤーになっていないか(Cookie を見る)。HUD が「マッチング中…」のままなら、その人は待機列にいる
- **しばらく待つと解散した**: セッション成立後、全員がつながるまで 30 秒。そろわないと解散して、HUD に理由が出る。机のボタンから始め直す
- **手元で開いたら WebSocket がつながらない**: `http://localhost:5173` で開く(`devenv` の既定は `IUBEO_ALLOWED_ORIGINS=http://localhost:5173`)。`127.0.0.1` や別ポートで開くなら、`IUBEO_ALLOWED_ORIGINS` にそのオリジンを足す
- **決着や切断の理由が知りたい**: console を見る。`[gameFlow] セッションとの接続が終わった (code=…, reason=…)` と `[game] 決着: …` に出る
- **手元でフェーズが長い**: 付録 B で短くする

## 付録 A: 手元で起動する

`devenv` の shell の中で、リポジトリのルートから:

```sh
devenv up
```

これで backend(`air`、`http://localhost:8080` 相当)と frontend(`pnpm dev`、`http://localhost:5173`)が立つ。
backend のログに `listening` が出て、frontend のログに `Local: http://localhost:5173/` が出たら準備完了。**3 人とも `http://localhost:5173` を開く。**

ブラウザを 3 つ(Cookie を分ける。macOS の Chrome):

```sh
open -na "Google Chrome" --args --user-data-dir=/tmp/iubeo-p1 http://localhost:5173
open -na "Google Chrome" --args --user-data-dir=/tmp/iubeo-p2 http://localhost:5173
open -na "Google Chrome" --args --user-data-dir=/tmp/iubeo-p3 http://localhost:5173
```

dev パネルは `?debug` を付けたときと F9 / F10 / Shift+F10 のときだけ出る。**`?debug` を付けなければ、手元でも本番と同じ見え方**になる。

## 付録 B: 手元で短く回す

リポジトリのルートに `.env` を作る(git 管理外。`devenv` の既定より優先される):

```sh
# 動作確認用。1 フェーズ・短い締切
IUBEO_MATCH_SIZE=3
IUBEO_PHASE_COUNT=1
IUBEO_PHASE_DURATION=25s
IUBEO_INTERMISSION_DURATION=5s
IUBEO_BYPASS_DURATION=20s
IUBEO_FIRE_DURATION=5s
```

- 変更したら `devenv up` を再起動する
- `IUBEO_PHASE_COUNT=1` にすると、3 人で 1 件ずつ終えるだけで最終フェーズを生き残れる。**victory の確認が一番確実**
- `defeat` の確認は、この設定で 3 人とも何もしないだけ
- 既定(3 フェーズ)に戻すには `.env` を消して再起動する

## 付録 D: 1 人で試す(CPU が足される)

人数がそろわなくても、待機列に一定時間たつと足りない分を **CPU** で埋めてセッションを作る(デバッグ用。`IUBEO_CPU_FILL_AFTER`、既定 30s、`0` で無効)。

- CPU は接続しないが、`player.kind = "cpu"` のプレイヤーとして席に座る。**開始は人間全員の接続だけを待つ**ので、1 人でも始まる
- CPU はフェーズごとに自分のノルマを約 1.2 秒おきに自動で片付ける(`read_edit` の対象を人間が持っている間は待つ)。火はつけない
- 見た目は、位置をサーバーが持たないので、フロントがその場で円を描いて歩かせている(すりガラスの向こうの影として見える程度)
- 人間が全員脱落しても、CPU が生きていれば敗北にはならず、ライターの時間切れで `victory` になる(デバッグ用の割り切り)

手元で 1 人 + CPU にするには、`.env` に次を足して再起動する(`IUBEO_MATCH_SIZE` は既定の 3 のままでよい。足りない 2 人が CPU になる):

```sh
IUBEO_CPU_FILL_AFTER=3s
IUBEO_PHASE_COUNT=2
IUBEO_PHASE_DURATION=30s
```

`IUBEO_MATCH_SIZE=2` にすれば「人間 1 + CPU 1」の最小構成になる。

## 付録 C: ヘッドレスでの自動確認(参考)

人手の代わりに、ヘッドレス Chrome で通しを自動で回せる。

- **1 人**(`IUBEO_MATCH_SIZE=1`): 机のボタン → フェーズ表示 → 締切で脱落 → `[game] 決着: defeat` → room 復帰
- **3 人**(`IUBEO_MATCH_SIZE=3`、既定の 3 フェーズ × 30 秒): ブラウザのコンテキストを 3 つ作り、room → マッチング → sandbox へ。各フェーズで自分のタスク(`read_edit` / `write` / `image_generation`)をこなし、最後のフェーズを生き残って**ライターで火をつけて `victory`** → 3 人とも room へ復帰(実測で 1 戦 約 2 分)

3D の照準は使わない(WASD とマウスでの移動は自動化が不安定なため)。マッチングは机のボタンの実クリック、それ以外の操作はフロントのモジュール(`objectManager.interact`)経由で要求を送る。照準とクリックの経路は、1 人の通しで別に確認している。

記録は、DOM の変化(rrweb)と数秒ごとのスクリーンショットで残せる(rrweb は `package.json` には入れず、その場で読み込む)。確認のときに作ったリプレイは `frontend/e2e-replay/index.html` をブラウザで開くと見られる(ローカル限定。git 管理外)。3D は rrweb に映らないので、右下のスクリーンショットで補う。スクリプトは `frontend/e2e-replay/run-e2e3.mjs` に置いてある(`/tmp/rrweb-all.min.js` が要る)。
