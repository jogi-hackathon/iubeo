# 6 つのこだわり

## ブラウザへのこだわり

名前: ブラウザ
色: #1d6fe0

> ゲーム内の PC のブラウザは、iframe でもモックでもなく Firefox のエンジンそのものです。firefox-wasm をフォークして JIT と日本語の表示を改善しました

- 本物の Firefox のエンジンを Wasm で動かした
  - iframe でも画面のモックでもない
- firefox-wasm をフォークして JIT と日本語表示を改善した
  - github.com/thirdlf03/firefox-wasm
- Wisp で TCP/UDP を WebSocket の上に通した
- 検索画面を Brave Search API で自作した
  - Google 検索だと Bot と判定されるため
- 開いたページの中身を読み取り、お題に合っているかを Workers AI の Clef で判定した

> wrangler ではなく、cf を使いました

- wrangler ではなく cf を使った

## 通信パフォーマンスへのこだわり

名前: 通信パフォーマンス
色: #2a9d5c

> 計測の仕組みを先に作り、20Hz の位置を 25 バイトのバイナリにして受信量を 86% 減らしました

- 計測の仕組みを整備した
- 20Hz の位置だけを 25 バイトのバイナリにした
  - 1 クライアントの受信ペイロード 11,945 → 1,700 B/秒(−86%)
- 33 MB のブラウザの wasm をゲームの起動中に読み込んでおいた
  - 通信環境が悪くても体験を損なわないように工夫した

## ボイスチャットへのこだわり

名前: ボイスチャット
色: #9b5de5

> ボイスチャットは MoQ で Opus を送り、ゲームの座標で相手ごとに距離で聞こえ方を変えました

- Opus を 1 フレームずつ MoQ の datagram で送った
  - 再送を待たないので、遅れが溜まらない
- ゲームサーバーの座標で相手ごとに距離減衰をかけた
  - 10 m で 1/2、20 m で 1/4
- 毎フレーム、カメラを聞き手にして、相手の声を HRTF で左右・前後に定位した
- セッションに紐づいた JWT で別のゲームに声が漏れないようにした
- VC サービスと MoQ リレーは自前の VPS で動かした
  - ゲームサーバーを切り離して、VC が使えなくなってもゲームを続行できるようにした

## Three.js へのこだわり

名前: Three.js
色: #ffd60a

> Three.js と React Three Fiber を選び、部品を組み合わせる形で、ゲームエンジンが受け持つ部分を自分たちで作りました

- Three.js + React Three Fiber で、ゲームを部品の組み合わせで作った
  - 当たり判定は <BVHCollider>、AO のベイク対象は <BakeTarget> で包むだけ
  - 同じ部品を room・sandbox・test、そしてこのスライドでもそのまま使い回した
  - Babylon.js は機能が多すぎてバンドルも大きく、AI で書くと品質が落ちた
- ゲームエンジンが受け持つ部分を自分たちで作った
  - 各種マネージャー・コントローラ
  - オブジェクト・コライダー・シェーダーのウォームアップ・ライトベイク
- ロード画面の間に描画の準備を終え、プレイ中に引っかからないようにした
  - 隠れている物や後から出る火などのエフェクトも裏で 1 度描き、シェーダーを先にコンパイル
  - その見本を持ち続け、一度消えた物が再び出るときも再コンパイルさせない
- 3D モデルのファイルは使わず、形をすべてコードで組み立てた
  - AI エージェントが読んで理解し、そのまま直せることを優先した
