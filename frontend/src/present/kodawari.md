# 6 つのこだわり

## ブラウザへのこだわり

名前: ブラウザ
色: #1d6fe0

> ゲーム内の PC のブラウザは、iframe でもモックでもなく Firefox のエンジンそのものです。firefox-wasm をフォークして JIT と日本語の表示を改善しました

- 本物の Firefox のエンジンを Wasm で動かした
  - iframe でも画面のモックでもない
- firefox-wasm をフォークして JIT と日本語表示を改善した
  - github.com/thirdlf03/firefox-wasm
- Wisp で TCP/UDP を WebSocket の上に通した
- 検索画面を Brave Search API で自作した
  - Google 検索だと Bot と判定されるため
- お題に合っているかは Workers AI の Clef で判定した

## cf へのこだわり

名前: cf
色: #f4a261

> インフラは wrangler ではなく、ベータ版の新しい CLI cf を使い、TypeScript 1 ファイルに書きました

- wrangler ではなくベータ版の新しい CLI cf を使った
- インフラを cloudflare.config.ts 1 ファイルに型付きで書いた
  - Worker 3・コンテナ 2・Durable Object・KV・Workers AI・Rate Limit
- Worker の入口を import で参照した
  - ファイルを動かすと型検査で気づける
- ドキュメントに無い挙動に実機で当たりながら進めた
  - 既定の設定ではコンテナに署名鍵を渡せず Go サーバーが起動しなかった

## パフォーマンスへのこだわり

名前: パフォーマンス
色: #2a9d5c

> 計測の仕組みを先に作り、20Hz の位置を 25 バイトのバイナリにして受信量を 86% 減らしました

- 計測の仕組みを作り、道具の誤りから先に直した
- 20Hz の位置だけを 25 バイトのバイナリにした
  - 1 クライアントの受信ペイロード 11,945 → 1,700 B/秒(−86%)
- 33 MB の wasm を起動の裏で取っておいた
  - 4G で PC のブラウザが使えるまで 93.7 秒 → 1.3 秒
- 大阪のコンテナに 9 クライアントでつないで実測した
  - RTT p50 56.8ms・20Hz を維持・切断 0

## 立体音響へのこだわり

名前: 立体音響
色: #9b5de5

> ボイスチャットは MoQ で Opus を送り、ゲームの座標で相手ごとに距離で聞こえ方を変えました

- MoQ / WebTransport の datagram で Opus を送った
- ゲームサーバーの座標で相手ごとに距離減衰をかけた
- セッションに紐づいた JWT で別のゲームに声が漏れないようにした
- VC サービスと MoQ リレーはチームメンバーが別ホストで動かした

## Three.js へのこだわり

名前: Three.js
色: #ffd60a

> Babylon.js ではなく Three.js を選び、ゲームエンジンが受け持つ部分を自分たちで作りました

- Babylon.js ではなく Three.js + React Three Fiber を選んだ
  - Babylon.js は機能が多すぎてバンドルも大きく、AI で書くと品質が落ちた
- ゲームエンジンが受け持つ部分を自分たちで作った
  - 当たり判定と一人称の移動・シーン遷移・TSL のポストプロセス・シェーダーのウォームアップ・AO の GPU ベイク
- 状態の送り元を差し替えられるようにした
  - チュートリアルはブラウザ内の簡易サーバー、本番は Go のサーバー
